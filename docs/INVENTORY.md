# Inventario y grado de verificación

Consulta del 10 de octubre de 2026 para construir Nexo Kit: desarrollo general en Windows con Claude Code y Codex CLI. El inventario reúne las dos investigaciones recibidas y la inspección adicional. No convierte una descripción comercial en una función comprobada.

## Cómo leer la evidencia

- **C**: se leyó código, manifiesto, script o estructura que implementa la técnica en esta fase; no significa que se ejecutara.
- **D**: documentado en README o instrucciones inspeccionadas; comportamiento no probado aquí.
- **P**: hallazgo de la investigación anterior de esta conversación, con enlace de procedencia; no revalidado en esta fase.
- **N**: no demostrado o contradictorio. No se usa como garantía del kit.

Las inspecciones C y D de los doce repos adicionales están fijadas por SHA, con archivos y límites, en [research-extra.json](research/research-extra.json) y [research-memory.json](research/research-memory.json). Las cifras de estrellas no intervienen en la selección técnica. No se ejecutó código de terceros ni sus suites. Las pruebas propias de Nexo se documentan separadamente.

## Contradicciones resueltas o conservadas

| Afirmación recibida | Evidencia y resolución |
|---|---|
| Último push equivale al último commit activo | Son medidas distintas. HEAD inspeccionado: CCH 06-09-2026, Compound 07-10-2026 —08-10 UTC—, Matt 09-10-2026. La API devolvió 403; no se pudo revalidar pushed_at para explicar la diferencia. |
| openai/skills es el catálogo actual | La investigación anterior registró su deprecación y remisión a openai/plugins. No se instala la ruta histórica en Nexo. |
| ECC es el único ciclo completo de aprendizaje | Hermes tiene un ciclo posturno implementado. La exclusividad no se sostiene; no se infiere que uno sea más eficaz. |
| Compound obliga a capturar aprendizaje cada vez | Su skill exige selectividad y permite no escribir nada. Se adopta ese filtro. |
| CCH valida cada comando | Su propio código/documentación limita cobertura por evento y host; los hooks no son una barrera universal. |
| context-mode tiene licencia “propia” | LICENSE inspeccionado identifica ELv2. Nexo no incorpora su código. |
| pro-workflow no tiene licencia | package.json declara MIT, pero no se encontró el texto LICENSE. Se conserva la incertidumbre; no se redistribuye su implementación. |
| Claude-mem captura cada herramienta | El handler filtra eventos y evita recursión; el conjunto de hooks también difiere entre hosts. |
| Hermes busca sesiones con resúmenes LLM | El README dice eso; el módulo actual session_search_tool.py declara que devuelve mensajes reales de SQLite sin llamadas LLM. El inventario prioriza el mecanismo inspeccionado y conserva la divergencia. |
| npx, README Windows o un .exe demuestran soporte nativo completo | Solo muestran una ruta o una declaración. Se exige una prueba propia del comportamiento correspondiente. Nexo no hereda validación de upstream. |

Los mecanismos marcados P son referencias de diseño, no una auditoría exhaustiva renovada. Ninguna afirmación de popularidad, ahorro de tokens, velocidad, autonomía de horas o calidad del modelo se usa como resultado verificado.
